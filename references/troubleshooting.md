# 出现问题时怎么处理

本页同时给用户和Agent使用：先把问题说清楚，让用户完成需要人工控制的环境修复，再从失败步骤继续。不要用反复下载、反复渲染或绕过系统保护代替修复。

## Agent的暂停与恢复规则

1. 先区分输入／参数、网络／安装、宿主能力、引擎／资源、输出验证问题。不要把所有错误都说成“模型不支持”或“照片不好”。
2. 读取工具实际的 `code`、`message`、`remedy` 和日志。只做与错误相关的有限只读检查，例如文件存在、Python版本、可用空间、一次连接检查。
3. 网络断开、代理／证书、账号登录、程序包下载、系统权限、缺少执行能力等问题交给用户。给出修复动作、成功验证命令，然后暂停依赖它的步骤。
4. 不对同一错误自动反复重试。不要私自关闭防火墙／杀毒、绕过SSL、改代理／DNS、全局改pip源、下载不明DLL／exe、索取密码／令牌或扩大系统权限。
5. 用户明确回复“已修复，可以继续”后，先验证失败点，成功后继续；错误变了就报告新事实。过去几分钟不代表用户已经修好。
6. 不把失败目录、旧成果、未经校验的预览或计划当成功。不重复原样执行已经内存／磁盘不足的渲染。缩图、改后端或改格式，先说明改变，由用户选择。

用户在本次任务中已同意的操作不必重复请求，但明确需要用户完成的环境修复不能靠等待或猜测替代。

## 可以直接使用的反馈格式

> **目前停在：** 安装依赖，第4步。  
> **实际问题：** 下载 `OpenImageIO` 时访问 `files.pythonhosted.org` 超时，命令退出失败。  
> **影响：** PSD依赖不齐，暂不能处理照片，没有生成本次合格输出。  
> **需要你做：** 检查本机网络／代理是否能访问该域名，或提供适配Python3.13和本机系统的可信离线包。不要关闭证书校验。  
> **修复后怎么确认：** 重试原来失败的pip命令一次，再执行依赖导入检查。  
> **恢复方式：** 处理好后回复“可以继续”，我先验证，再继续配置和小图测试。

必须换成本次**实际包名、域名、错误和步骤**，不能把模板示例当已发生事实。可引用错误最后几行；分享日志前去掉凭据、私有下载令牌和无关私人目录。排错通常不需要公开用户照片。

## 1. GitHub／下载地址连不上

常见表现：`Could not resolve host`、连接超时、connection reset、下载停住、HTTP403／429、无法clone。

用户需要：

1. 用自己的浏览器打开错误中的真实域名，判断全网断开、某站不可用、账号问题还是URL失效。
2. 检查自己控制的代理、组织网络限制或登录状态。网络设置由用户处理。
3. 仅发布附件失败时，从同一上游官方Releases页面手动下载，核对文件名、平台、版本与哈希。Agent不自动切到非官方搬运站。
4. 访问频率受限时等用户确认解除，不通过切换账号／令牌躲避限制。

Windows只读检查示例：

```powershell
Test-NetConnection github.com -Port 443
```

`TcpTestSucceeded=True`只证明端口能连，不证明附件、登录和完整下载成功。具体附件仍要下载完成并校验，不能用首页打开冒充所有问题已解决。

## 2. pip超时、代理或SSL问题

常见表现：`ReadTimeoutError`、`ProxyError`、`SSLError`、`CERTIFICATE_VERIFY_FAILED`，访问 `pypi.org`／`files.pythonhosted.org` 失败。

由用户检查网络是否能访问日志里的域名、系统日期时间、自己的代理配置，以及组织网络是否需要正规证书／认证。也可由用户提供适配系统、CPU和Python3.13的可信wheel／离线包。

不要追加 `--trusted-host`、禁用SSL或私自全局改镜像／证书。如果用户自己选择可信镜像／离线源，应由用户提供并确认方式，再做任务需要的安装。

修复后重试**原来失败的命令**，不是换个无关包。教程用 `--retries 0 --timeout 30`，避免把明确失败隐藏成长时间重试。安装成功再做导入检查与doctor。

## 3. 找不到Python，版本或架构不对

表现：`py`／`python`无法识别、打开商店、版本不是3.13、包不支持解释器。

由用户安装／选择普通64位Python3.13，新开终端验证：

```powershell
py -3.13 --version
py -3.13 -c "import struct; print(struct.calcsize('P') * 8)"
```

应分别显示3.13.x和 `64`。不要覆盖系统Python，不因命令找不到而卸载其他项目解释器。错误版本的venv应让用户选择新的环境目录，不能自动清空旧环境。

## 4. 包没有匹配发行版，或需要编译

表现：`No matching distribution found`、`Requires-Python`、`Failed building wheel`、缺C/C++编译器／系统库。

Agent给出失败包名／版本、Python版本、操作系统、32／64位、完整命令及最后错误。用户选择受支持环境、提供适用wheel或自行准备构建依赖。

不要擅自安装编译器、驱动、系统开发包或改到未知旧版本；不能为凑doctor通过而删必需包。用户明确只用Windows原生后端时，可以不装Python后端特有依赖，PSD和所选后端的实际依赖仍须满足。

## 5. 缺SpektraLab host／资源，或下载错包

表现：`backends.spektralab=false`，找不到 `spektralab-host.exe`／`host/engine/`，或把DMG／安装器当作运行程序。

用户核对官方资产的系统／CPU、解压后的真实目录和版本：

```powershell
Test-Path "$Runtime/apps/SpektraLab/spektralab-host.exe"
Test-Path "$Runtime/apps/SpektraLab/host/engine"
```

`spektralab.exe`不能替代host，不要重命名GUI或拼凑材料数据。上游同名附件可能被更新，记录实际文件名与哈希；新包不能未经测试承诺与历史演示一致。

若官方包没有适配器所需host，让用户选择合适官方版本或Python路线。用户只选Lab时不可私换Python。doctor检查存在性，不代替原生引擎／GPU的真实小图测试。

## 6. LittleCMS2缺失或加载失败

表现：`float_icc_ready=false`、`ICC_DEPENDENCY_MISSING`、DLL／共享库无法加载。

1. 用户检查正规GIMP／Krita／系统LCMS2安装。
2. 非默认位置由用户给出实际库路径，不能仅猜“应该在这里”。
3. Windows中Python与DLL架构需一致，保留正规安装完整依赖，不从不明网页补同名DLL。
4. 临时PowerShell的 `SPEKTRA_LCMS2` 不会传到已运行的豆包。用户正确设置用户环境变量后需重启宿主，或采用工具能自动发现的正规安装位置。

以doctor实际浮点ICC转换成功为准，不用“有同名文件”替代验证。不得删ICC、先降8位或改色彩空间标签绕过失败。见[安装文档第5步](integration.md#第-5-步准备-littlecms2-色彩管理库)。

## 7. 宿主只有聊天或云沙箱

表现：Agent无命令执行工具、只能返回文字；云端 `/mnt/...` 找不到个人电脑 `C:/photos/...`；附件已上传却没有执行机器的落盘路径。

这属于宿主能力／执行位置问题，不是胶片算法失败。用户需选择能读本机文件并执行Python的宿主／工作模式，或由开发者接入 `tool_bridge.py`。必须云端运行时，也需在该云机器上准备引擎和用户允许使用的输入文件，不能假装云路径与个人电脑硬盘自动互通。

Agent应明确自己在哪台机器、拥有什么工具，等待用户提供能力或正确路径。不要让用户反复换本机路径拼法，也不能把function-call JSON当成真实计算完成。

## 8. 路径不存在、无权限或输出目录已存在

- 确认照片实际保存在**执行机器**，不是只有手机相册、浏览器附件链接或另一台电脑的路径。
- 使用含扩展名的完整文件路径，引号保留空格。教程示例必须替换成自己的真实文件。
- 用户选择有写权限的普通目录，按需自己授予访问权限；Agent不自动提权或修改系统权限。
- 输出已有内容就换新名字，如 `result02`。不要删旧成果、覆盖原片或把历史成功项当作新输出。

## 9. 内存／显存／磁盘不足，或者原生渲染崩溃

记录输入尺寸、后端、失败阶段与错误，说明未完成的输出，不重复原样执行。用户可释放空间／内存、换机器，或明确选择缩小测试尺寸、关闭重复ZIP、换后端。

不能静默改变原尺寸。用户选择降尺寸后要说实际像素；`--no-archive`只省重复ZIP，不缩PSD。自动选PSB不增加物理资源。系统commit预算不足可能在原生引擎启动时就出现，不能把它误写为源文件不存在，也不能自动关闭用户其他程序。

首次Python运行可能有数值计算编译准备，不应因短暂无终端输出就立即判死；结合进程、日志及明确超时信息判断。已经返回资源错误或异常退出就停下，不无限等待／重试。

## 10. 文件格式／ICC不支持

RAW／HDR／HEIC由用户先显影或转换为支持的SDR RGB文件；16位CMYK明确拒绝。RGB文件带不兼容非RGB profile时，用户需按自己的色彩流程提供正确输入。

不要自动把16位降8位、把场景线性数据伪装sRGB、剥profile或覆盖源片。可建议用户另存正确RGB SDR副本，并披露本次究竟用了哪份文件。

## 11. 生成文件但validation失败，或PS不一致

校验失败不按合格成果交付。保留验证器名称、实际后端、尺寸与错误摘要；不能只凭预览正常忽略错误，不能直接放宽阈值。

PS中先确认打开本次文件，保持默认层顺序／混合方式／不透明度，核对文档色彩空间及混合设置。全部设50%、重排差分层、改底图、变更混合Gamma都可能改变合成；默认值读本次 `layers.json`。

默认状态仍不一致时，用户可提供配方／验证摘要、PS版本和相关设置。公开Issue不需要原始私人照片；若需样例，用自己有权公开的最小文件替代。开源合成器通过不等于所有Adobe版本都已认证。

## 用户说“修好了”之后

1. 复核实际失败点：文件哈希、包导入、路径、运行时配置或doctor。
2. 只补未完成的步骤，不重下所有包、重建所有环境或重跑成功照片。
3. 环境就绪后按原请求，或用户明确同意的小图条件，执行一次。
4. 校验成功才交付，说明实际后端、尺寸、格式与路径。
