# Spektra Color Grade：用对话生成可继续编辑的胶片 PSD

告诉 Agent 你想选哪种胶片、颗粒多一点还是少一点，再给它一张照片。这个 Skill 调用本机胶片模拟引擎，生成 **16 位、8 图层的 PSD／PSB**，并附参考成片、压缩对照和可续改的配方。

它适合已经使用 Photoshop、希望把胶片模拟接入现有调色流程的人。你负责审美，Agent 负责传递参数，固定工具负责计算、分层、校验和交付。默认不使用视觉大模型，也不把照片上传给生图服务。

本仓库是对 [SpektraLab](https://github.com/JamesQiu2005/SpektraLab)／[spektrafilm](https://github.com/andreavolpato/spektrafilm) 的额外封装，**安装 Skill 不等于安装胶片引擎**。ZIP 不包含引擎程序、材料数据、Python 环境、Photoshop、测试照片或作者的本地配置。首次需要按下面步骤准备环境。

## 先选你现在的情况

|你的情况|从哪里开始|
|---|---|
|已有能执行本地命令的 Agent，本机也配置过引擎|按“安装到豆包或其他 Agent”导入，再运行 `doctor`|
|第一次使用，电脑没有运行环境|先看[完整安装教程](references/integration.md)；可按 Python 路线固定源码准备，或选择官方 Windows 原生包并现场小图自测|
|模型只能聊天，或只在云沙箱执行|先解决宿主的本地执行能力；只上传 ZIP 或输入本机路径不能让云端读取你的硬盘|
|已遇到下载失败、缺包或找不到文件|按[故障处理](references/troubleshooting.md)检查；环境问题交给用户处理后再继续|

**既有端到端验收的平台是 Windows。** Python 路线固定已验证的源码提交；Windows 原生适配器需要包含 host 的官方包。上游新下载资产可能与历史测试包不同，当前 beta.3 的目录和协议启动已核对，完整图像渲染仍需首次小图测试。macOS／Linux 的对应命令已提供，但不能据此称所有系统都已完成端到端验收。具体组合与边界见[已测试版本](references/tested-versions.md)。

## 安装到豆包或其他 Agent

下面是用户操作顺序。宿主按钮名称可能变化，但“导入 Skill → 启用 → 在有本地执行能力的工作对话中使用”这三个条件不变。

1. 打开[本仓库 Releases](https://github.com/Leipengpeng/spektra-color-grade/releases/latest)，下载 `spektra-color-grade.zip`。
2. 技能包顶层应是 `spektra-color-grade/`，里面能直接找到 `SKILL.md`、`scripts/`、`references/`。不要把测试素材或运行环境重新打进 ZIP。
3. 在豆包桌面端找到“技能／技能管理”，选择“添加／上传技能”，选中这个 ZIP。若宿主使用本地技能目录，就解压到该目录，保留完整结构。
4. 确认技能列表出现 **Spektra Color Grade**，并启用它。新建工作对话，或从技能卡片选择“在对话中使用”。
5. 使用能够访问本机文件、执行本地 Python 的模式。仅在网页里与模型聊天，不代表已经有这些能力。
6. 发下面这句话，让 Agent 先讲教程、再检查环境：

   > 使用 Spektra Color Grade。先给我首次使用教程，展示胶片菜单和可调参数，然后运行 doctor。环境没准备好就告诉我缺什么，不要先处理照片。

7. 首次准备环境时，按[安装教程](references/integration.md)操作。`doctor` 需显示所选后端可用、`psd_ready=true` 和 `float_icc_ready=true`。本Skill先让这两项都通过，再处理正式照片。

**成功标志：** Agent 展示了胶片菜单，检查了实际本地路径和后端，没有把“装了 Skill”误报为“引擎已经可运行”。

导入到新宿主会产生新的 Skill 副本。原目录的 `runtime.local.json` 不会自动随 ZIP 分发，必要时在新副本里再执行 `configure`。见[配置安装后的 Skill 副本](references/integration.md#配置安装后的-skill-副本)。

## 第一次处理照片：可以直接这样说

先把照片保存到执行机器的硬盘。路径只是示例，请换成真实存在的文件：

> 处理本机 `C:/photos/portrait.jpg`。选 1，Portra 400，整体力度 0.8，颗粒 0.2，光晕 0.25，其他默认。保留原尺寸，输出到新的 `C:/photos/result01`，生成分层 PSD 和压缩对照。不要进行自动审美评分。

也可以只给偏好：

> 选 2，颗粒少一点，光晕先按默认。先给我一版，我来判断效果。

宿主需要附件时，可以上传压缩预览，并说明本机原尺寸文件路径。**附件预览和本地处理源是两件事**；Agent 应核对实际输入路径、尺寸和输出尺寸，不能悄悄把压缩附件当成全尺寸源。

只有工具返回 `status=ok` 且校验通过后才能交付。失败时要给出问题和下一步，不能拿旧结果、部分目录或一张正常预览冒充成功。

### 胶片菜单

|编号|名称|说明|
|---|---|---|
|1|Portra 400 · 自然人像|三种材料起点之一|
|2|Gold 200 · 标准胶片|三种材料起点之一|
|3|Ektar 100 · 标准胶片|三种材料起点之一|
|4|Portra 400 · 清透淡彩|基于 Portra 的创作配方|
|5|Portra 400 · 冷调电影|基于 Portra 的创作配方|
|6|黑白 · 灰度后处理|Portra 渲染后转灰度，不是真实黑白材料模拟|

即 **3 种胶片材料、6 个配方**。名字是起点，不保证每张照片都呈现固定色调；相纸目前固定为 Portra Endura。

### 一开始只调这三项

|参数|怎么理解|可填范围|
|---|---|---|
|整体力度 `strength`|保留多少处理效果；0 趋向原片，1 使用完整处理|0–1|
|颗粒 `grain`|0 关闭；越高通常越明显|0–1|
|光晕 `halation`|控制散射与晕光；可先保留默认 0.25|0–1|

明暗、冷暖、反差、饱和度等见[完整参数教程](references/user-guide.md)。第一次不需要填满所有选项。

## 会交付什么

每次使用一个**新的输出目录**，原照片不覆盖。默认保留 EXIF 转正后的原尺寸，另生成压缩 JPEG 供低流量审片。

|文件|用途|
|---|---|
|`graded.psd` 或 `graded.psb`|16 位分层文件，在 PS 中继续编辑|
|`graded.tif`|16 位参考成片，核对默认图层合成|
|`preview.jpg`、`comparison.jpg`|压缩预览和前后对照|
|`recipe.json`|记录原片、参数、引擎和尺寸，用于续改|
|`layers.json`|每层默认不透明度、混合方式及实际增强余量|
|`validation.json`|文件和图层重建的技术校验，不是美学分数|
|`PS使用说明.md`|本次分层文件的使用说明|
|`delivery.zip`|默认交付包；大图可用 `--no-archive` 省略|

超出 PSD 格式限制时自动选 PSB。输出不设统一总像素上限，但受磁盘、内存／显存、引擎和格式上限约束，**不承诺无限分辨率**。资源不足时报告问题，由用户决定释放空间、换机器或明确降低尺寸，不能静默缩图。

## 在 Photoshop 里怎么调

1. 打开实际返回的 PSD／PSB。先保持图层顺序、混合方式和默认不透明度，查看默认成片。
2. 找到“胶片颗粒”，降低不透明度以减弱颗粒；有余量时可提高到 100%。
3. 找到“散射与光晕”，用不透明度调这一层的贡献。只想影响局部时，可在 PS 中手工加蒙版。
4. 原片位于底部“原片底图（保留）”。对照时临时只显示这一层，之后恢复全部默认可见性。
5. 差分层默认不透明度会自适应，不一定是 50%，也不一定有增强余量。复位请看本次 `layers.json`，不要把所有层统一设成 50%。

八层从底到顶：原片底图、基础调色、全局冷暖与力度（基础条件差分）、曝光与印相、散射与光晕、DIR 显影扩散、胶片颗粒、透明后续修饰层。

这些层是**这张照片、这套参数和这次渲染的效果快照**。改不透明度、蒙版、底图或顺序属于创作编辑，不会重算胶片物理模型。“全局冷暖与力度”层只保存基础阶段的条件差分，也不是整图参数滑杆。真正更换胶片或全局参数，请根据配方重新生成。详见[PSD 工作流与限制](references/psd-workflow.md)。

## 不满意时怎么继续改

保留 `recipe.json`，继续在同一对话中说：

> 沿用 `C:/photos/result01/recipe.json`，再暖一点，整体效果轻一点。输出到新的 `C:/photos/result02`，其他参数和尺寸保持不变。

普通续改只需要配方、新偏好和新目录。不要重复传新胶片编号，除非确实要换胶片；重新选择编号会回到新配方起点。

命令行等价示例：

```powershell
& $Py "$Skill/scripts/spektra.py" psd --recipe "C:/photos/result01/recipe.json" --intent "再暖一点，整体效果轻一点" --output "C:/photos/result02"
```

`$Py` 和 `$Skill` 由[安装教程](references/integration.md)设置。新开 PowerShell 窗口后需要重新设置变量，不需要重装依赖。

## 出现问题时的规则

Agent 应告诉用户 **哪一步失败、具体错误、需要用户做什么、修好后用什么命令验证**，然后暂停依赖该问题的步骤。网络断开、代理／证书问题、GitHub 或 PyPI 下载失败、程序包无法安装、宿主没有本地执行能力，不能靠反复渲染解决。

用户修复后明确回复“已处理，可以继续”，Agent 再从失败步骤恢复。不得自动关闭防火墙／杀毒、绕过 SSL、替换不明下载源、索要密码或令牌、无限重试，也不得把环境问题归咎于照片。完整分类与反馈格式见[故障处理](references/troubleshooting.md)。

## 当前范围

- 推荐 8 位 SDR JPEG／PNG，以及 16 位 SDR RGB PNG／TIFF。嵌入 RGB ICC 时用 LittleCMS2 浮点色彩管理；无 ICC 按编码 sRGB 解释并记录。
- RAW、HDR、HEIC 先显影或转换为受支持的 SDR 文件；16 位 CMYK 明确拒绝。8 位源输出成 16 位不能恢复已丢失的信息。
- 默认在本机运行固定胶片流程，不自动上传全尺寸照片或 PSD，不自动审美评分。宿主自身是否上传附件或对话，取决于它的设置和权限。
- 两后端有实现差异，同参数不保证逐像素一致。开源合成器校验和某次 PS 测试不代表所有 Photoshop／其他编辑器版本全面认证。
- 当前没有 XMP 导出，也不是 PS 智能滤镜插件。深入说明见[算法、LUT 与 XMP 分析](references/algorithm-and-export.md)。
